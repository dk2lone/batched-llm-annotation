# Gate A: within-batch LLM annotation dependence

This package measures whether classification errors are correlated among documents labeled in
the same prompt. It is staged, resumable, and refuses to interpret runs with too few model errors
or excessive parse failures.

No real-model result exists yet. `artifacts/smoke/` was generated by a mock backend that reads the
gold labels to test the pipeline.

## 1. CPU verification

From this directory:

```bash
uv sync --extra dev
uv run pytest
uv run ruff check .
uv run mypy
uv run batchgate --config configs/smoke.toml smoke
```

Success means the tests pass and the smoke command reports an empty `failures` list. These checks
do not download data or model weights.

## 2. GPU environment and data freeze

On a Linux CUDA host:

```bash
uv sync --extra data --extra dev
uv pip install -r requirements-gpu.txt
uv run batchgate --config configs/full.toml prepare-data --allow-download
uv run batchgate --config configs/full.toml plan
```

The first two commands create the environment. `prepare-data` downloads the Civil Comments
validation split, freezes 2,000 targets and a disjoint 4,000-row filler pool, and records the
resolved dataset revision and checksums. `plan` creates an immutable 8,375-job manifest and
refuses later inference if its checksum changes.

Expected plan counts:

- 2,000 solo prompts
- 375 joint prompts, covering 2,000 targets under each of three batch assignments
- 6,000 length-matched filler prompts

Before inference, inspect the dry runs:

```bash
uv run batchgate --config configs/full.toml run --dry-run --phase primary
uv run batchgate --config configs/full.toml run --dry-run --phase controls
```

The exact Qwen tokenizer is checked again when vLLM loads. No prompt may exceed the configured
8,192-token context.

## 3. Primary GPU phase

```bash
uv run batchgate --config configs/full.toml run --backend vllm --phase primary
uv run batchgate --config configs/full.toml analyze
```

This executes 2,375 prompts: every solo prompt and 375 joint prompts. Results append to
`artifacts/full/raw/predictions.jsonl`; completed job IDs are skipped on restart. The analysis is
written to `artifacts/full/analysis/analysis.json` and `report.md`.

Stop if the verdict is `UNDETERMINED`, `AMBIGUOUS`, or `BOUNDED_NEGATIVE_CANDIDATE`. Continue to
the context control when the verdict is `NEEDS_FILLER_CONTROL`, which requires a joint ICC point
estimate of at least 0.02. `PROCEED_POINT_ONLY` is not claim-ready evidence.

## 4. Filler-control GPU phase

```bash
uv run batchgate --config configs/full.toml run --backend vllm --phase controls
uv run batchgate --config configs/full.toml analyze
```

This adds 6,000 prompts where each target is accompanied by 15 length-matched documents but only
the target is labeled. `FILLER_CONFOUNDED` means prompt length or neighboring text reproduces the
effect, so do not claim joint-label dependence. `PROCEED` means the point threshold, conservative
interval, permutation tests, error floor, parse-quality floor, and filler controls all pass.

Do not change thresholds after looking at predictions. Any changed config should use a new output
directory so the raw rows cannot be mixed.
