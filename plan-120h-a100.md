## The paper-sized question

**Working title:** *When the Batch Becomes the Cluster: Measuring False Precision in Large-Scale LLM Annotation*

When an LLM labels many text records by placing 16 records in each prompt, does the shared call create error dependence beyond item difficulty and prompt length? If so, how much does treating the resulting labels as independent rows misstate uncertainty for **mean reference-relative accuracy**?

The Big Data contribution is a measurement of a data-production choice that changes the usable information in a large annotation table. A labeling pipeline may produce thousands of rows cheaply, but its statistical unit may partly be the annotation call. The paper will link three measured quantities, for the *same* model-task-policy cells:

```text
shared-prompt annotation → excess within-call error covariance
                         → variance/coverage of mean accuracy
                         → whether retaining call IDs changes the analysis
```

This is a data-quality and uncertainty-quantification paper about large-scale text labeling with LLMs. It is **not** a new cluster-robust estimator, a general claim about all LLMs, a mechanism paper, or an assertion that batching always harms accuracy. The existing literature audit places novelty in the across-item covariance created by the annotation call and its controlled measurement, not in the mathematics of clustered standard errors ([audit](idea-stage/novelty-check-20260910/NOVELTY_REPORT.md)).

## What is already known, and what remains open

The completed Gate A pilot on Qwen3-8B and Civil Comments used 2,000 documents, batch size 16, and three assignments. It found joint-call error ICC 0.0754, a conservative decision interval [0.0182, 0.1314], and matched-length separate-call filler ICC 0.0048 ([pilot report](gate-experiments/a/artifacts/full/analysis/report.md)). The often-quoted design effect of 2.131 and effective sample size of about 938 are **exchangeable-ICC approximations**, not observed coverage. The pilot used one model-task cell and cannot establish recurrence. Joint accuracy was better than solo accuracy, so dependence and accuracy must remain separate endpoints.

All new claims below require fresh records or independently randomized calls, a frozen protocol, and retained first-response failures. The old pilot stays discovery evidence and is never pooled into a confirmatory p-value.

## One fixed, small panel

Use a 2 × 2 panel with batch size 16, greedy decoding, one frozen prompt template per task, and one pinned serving engine:

| | Civil Comments toxicity | Second large text task |
|---|---|---|
| Qwen3-8B | New-record replication anchor; old pilot shown separately | Fresh confirmatory cell |
| Mistral-7B-Instruct-v0.3 | Fresh confirmatory cell | Fresh confirmatory cell spanning both new axes |

The second task is chosen **before any joint outputs**: first try the [AG News](https://huggingface.co/datasets/fancyzhx/ag_news) training frame for four-class topic classification; use [MultiNLI](https://huggingface.co/datasets/nyu-mll/multi_nli) only if AG News fails the frozen solo-only information/capability screen. Do not choose the task by comparing batching effects. Civil Comments uses a fresh, disjoint sample from the [validation frame](https://huggingface.co/datasets/google/civil_comments), with the original 2,000 pilot IDs excluded. Pin exact dataset revisions, records, reference-label rules, checkpoints, tokenizer, prompt, response grammar, maximum output tokens, engine version, and seeds. For Civil Comments, call the outcome *disagreement with its reference label*, not proof of human annotation error. Audit the second dataset's license and labeling limits before freezing it.

The solo-only screen checks context fit, at least 98% parsable first responses, and enough errors for a useful covariance estimate. Freeze the error-information threshold and model replacement policy through CPU simulation before screening. A failed model-task cell remains in the published panel as uninformative; do not swap in a favorable joint result. If the second model or task cannot be selected under those rules, narrow the claim and do not say “across models and tasks.”

For each task, sample **2,048 distinct records** from its declared frame and use those same records for both models. Create **three independently randomized** batch assignments per model-task cell. Each item appears once per assignment, with position and length strata balanced. Run:

1. Joint calls on each 16-record batch.
2. Exact-neighbor target-only calls: show the same 16 records in the same order, but request one target label per separate call.
3. Solo calls as an accuracy and formatting comparator.
4. Fake batches built from independent-call labels under the frozen assignment generator.

The Qwen/Civil anchor also repeats the pilot's matched-length filler condition. Add a small, prespecified filler and serial-serving subset to the double-new cell; this tests whether a positive result is merely long context or serving-scheduler behavior. Interleave arms over execution time. Record every global call ID, item ID, batch membership, position, execution block, prompt/output token count, latency, first response, failure state, and GPU duration. A retry is a new linked call, never a replacement observation.

The primary phenomenon statistic is the signed, pair-weighted excess error covariance (\Delta_c=C_{joint,c}-C_{exact,c}\), as defined in [plan.md §5](plan.md). The fake-batch contrast is a falsification endpoint. Keep marginal error rate and paired accuracy change separate. Use the exact paired assignment generator for one-sided sharp-null randomization tests; do not shuffle labels without respecting repeated items, strata, and execution blocks. Report design-respecting effect intervals, the 0.002 absolute covariance floor from the full plan, and sensitivity bounds that count malformed outputs as correct, wrong, or whole-call failures. Cluster by call and account for the same items appearing in three assignments.

The old Qwen/Civil pilot has already influenced this design. The new Qwen/Civil run is a replication, while the **three other cells** form the fresh confirmation set. A pooled recurrence claim needs a prespecified equal-cell-weight signed contrast across those three cells and positive, practically meaningful contrasts in at least two, including the double-new cell; use Holm correction for named cell claims. A positive result in only the anchor is a bounded case study, not a panel result. The precise test and interval algorithms, Monte Carlo count, power, and multiplicity family must be frozen and simulation-checked before new joint labels are viewed.

## Direct Big Data consequence: one estimator, two cells

Do an actual repeated-call uncertainty experiment, but **only for mean reference-relative accuracy**, in two cells named before joint outputs: the new Qwen/Civil anchor and the Mistral/second-task double-new cell. Do not select cells after seeing their covariance. For each cell, define the target as expected mean disagreement over independent uniform 512-item samples **without replacement within a replicate** from the frozen item frame and random size-16 partitions under the exact operational batching policy. Replicates use independent draws and calls, although a frame item may recur across replicates. Freeze whether the finite-population correction is applied to both interval methods before outputs are opened. This is an LLM-policy/reference-label quantity, **not** gold-label population prevalence.

Use two disjoint random streams:

- **Reference stream:** 250 independent replicates, each with 512 sampled item appearances in 32 fresh calls, to estimate the target mean without using evaluation replicates. Verify the target estimate's Monte Carlo uncertainty is small relative to an evaluation interval; propagate that uncertainty in a coverage sensitivity analysis.
- **Evaluation stream:** at least 400 independent replicates per cell, again 512 item appearances and 32 fresh calls per replicate. An item may recur across replicates because each replicate is a new sample from the fixed frame; there is no reuse of an LLM output across replicates. Each replicate computes a nominal 95% i.i.d. interval and a prespecified call-aware interval for its mean disagreement.

Freeze the sample-size maximum at 1,000 evaluation replicates per cell based only on the A100 timing benchmark, before evaluation outcomes are opened. The minimum 400 gives roughly 1.1 percentage points of Monte Carlo standard error near 95% coverage; intervals around measured coverage must be reported. If the independent reference stream is too imprecise, do **not** claim measured coverage. Report the empirical variance of replicate means and the ratio to the average nominal i.i.d. variance instead. The i.i.d. method is the ordinary item-level 95% Wald interval. The call-aware method is a 95% t interval over the **32 call means** (31 degrees of freedom), with a whole-call bootstrap as sensitivity. Report interval width and empirical coverage for both. A claim of undercoverage requires the upper confidence bound on measured i.i.d. coverage to be below 95%, including reference-target uncertainty; do not call the correction “calibrated” from a favorable point estimate alone.

The practical variance endpoint is the empirical-to-i.i.d. variance ratio for this **same mean estimand**, with 1.25 as the prespecified meaningful floor. Estimate accuracy, covariance, variance inflation, and coverage separately. A positive ICC cannot be substituted for measured undercoverage. If only one of the two cells undercovers, the paper can say so for that cell, not for all batched labeling. The 120-hour study will not test Type-I error, regression, model rankings, or population prevalence.

## Claim gates and paper narrative

The paper should read as one argument: a high-throughput annotation workflow creates a call-level data lineage; randomized controls test whether that lineage changes error covariance; repeated production runs test whether ignoring it changes uncertainty. A table reports all four cells, including null or uninformative ones. One figure shows joint-minus-exact covariance and the same-cell variance/coverage comparison. Throughput and token cost show why batching is attractive, but no cost-optimality claim is made without a matched cost experiment.

Possible outcomes are prespecified:

1. **Strong bounded result:** New-record replication and fresh-panel recurrence pass; at least one frozen repeated-sampling cell shows meaningful variance inflation and statistically supported i.i.d. undercoverage. Claim that preserving call lineage matters for the tested large-scale text-labeling policies.
2. **Phenomenon without demonstrated damage:** Excess covariance recurs, but the mean-accuracy variance or coverage endpoint is small or imprecise. Publish the dependence measurement and a bound on practical consequences; do not say confidence intervals fail.
3. **Narrow or negative result:** Only the original setting works, exact-context controls explain it, or neither fresh task nor model replicates. Report the boundary and stop a broad Big Data claim. A five- or six-page paper is not guaranteed by the pilot.

The venue fit is substantive: statistical methods for big data, text annotation, uncertainty quantification, and LLM-based data mining.
