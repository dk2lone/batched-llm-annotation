# Research Proposal: The Future Chooses the Test Set

## Contribution statement

C1 contributes a controlled audit that freezes a historical recommendation task and every per-user prediction, then varies only the future observation horizon used to compute k-core eligibility. Its primary estimand tests whether future-conditioned admission shifts a frozen pairwise model gap beyond shifts produced by historically comparable cohorts. The method contribution is the controlled audit; whether real datasets exhibit a practically meaningful excess shift remains an empirical hypothesis.

## Fixed historical task

Freeze a training cutoff and test window. For every user with training history, select the chronologically last test-window interaction as one target, breaking timestamp ties by stable item ID. Define the pre-k-core universe \(U^*\) as users whose frozen target is in the training-item catalog. Train popularity and sparse item-kNN once on suffix-independent historical rows and save each user's Recall@20 difference \(d_u\).

## Horizon intervention and primary estimand

At each horizon \(h\), compute the same iterative k-core on records observed through \(h\). Let \(E_h(u)=1\) only when user \(u\) and the frozen target item lie in that core. Future records may change only \(E_h\). Historical rows, target labels, candidate catalog, model inputs, and predictions remain fixed.

The primary estimand is the change from the test cutoff \(t_0\) to the final observation horizon in the mean pairwise model gap among eligible users:

\[
\Delta_{\mathrm{sel}}=
\operatorname{mean}\{d_u:E_{h_{final}}(u)=1\}-
\operatorname{mean}\{d_u:E_{t_0}(u)=1\}.
\]

Interpret this shift using the share of newly admitted users and the difference between entrants' and incumbents' mean \(d_u\). This is an interpretation of the primary estimand, not a separate contribution.

## Historical-covariate-matched null

Real entrants are users outside the baseline eligible set who become eligible at the final horizon. Draw equally sized pseudo-entrant cohorts from the remaining baseline risk set, matching on training degree, activity during the 30 days before the test window, and target-item training popularity. Compute quantile boundaries once on \(U^*\) using information available by \(t_0\), then run 2,000 stratified draws.

When a stratum lacks donors, merge in a fixed order: nearest target-popularity bin, nearest recent-activity bin, then nearest training-degree bin, breaking equal-distance ties downward before upward. Require standardized mean differences below 0.1. If donors or balance remain inadequate, report the matched-null test as unsupported rather than changing it after seeing outcomes.

## Primary pilot gate

Use raw Amazon 2014 Beauty ratings. The only continuation test is the absolute change in the popularity-versus-item-kNN Recall@20 gap at the final horizon. It must exceed both the matched-null 95th percentile and an absolute 0.002 Recall@20 threshold. NDCG@10 and intermediate horizons are descriptive trajectories; a ranking reversal is secondary evidence.

## Controls and paper-stage bridge

Hash historical rows, target labels, candidate catalog, model inputs, and per-user predictions; all must remain invariant across horizons. The warm-universe construction must produce zero missing-user and missing-item fallbacks.

If the primary gate passes, run a 2×2 historical-training-mask/evaluation-cohort attribution on Amazon and a second dataset with a maintained contemporary recommender pair. This separates selection, filtered-training, and interaction effects and connects the isolated diagnostic to benchmark pipelines used in practice.

## Claim boundary

The proposal does not claim that changing cohorts changes averages is new. It claims a controlled fixed-history, fixed-prediction audit for testing whether future-conditioned benchmark eligibility selects model-relative difficulty beyond a prespecified historical null. A systematic real-world effect is claimable only after the empirical gate and replication pass. Temporal leakage, k-core sensitivity, provenance hashing, and train-only filtering remain prior concepts or controls.
