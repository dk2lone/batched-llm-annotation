# F1 — Catalogue-specific title advantage

### 1. Closest prior work

- Caliper: Probing Lexical Anchors versus Causal Structure in LLMs — https://arxiv.org/abs/2606.04915
- Benchmark Leakage Trap: Can We Trust LLM-based Recommendation? — https://arxiv.org/abs/2602.13626
- Do LLMs Memorize Recommendation Datasets? A Preliminary Study on MovieLens-1M — https://arxiv.org/abs/2505.10212
- On the Memorization Behavior of LLMs in Generative Recommendation — https://arxiv.org/abs/2606.17276
- Large Language Models are Zero-Shot Rankers for Recommender Systems — https://arxiv.org/abs/2305.08845

### 2. Is the contribution new?

No. Caliper already runs the design. Caliper removes the lexical anchor, holds the structure fixed, and reads the accuracy drop. F1 moves that design from causal reasoning to recommendation and adds a randomization test. The prompt tells me to kill routine domain transfers. F1 is one.

The two memorization papers and Benchmark Leakage Trap already occupy the recommendation half. Hou et al. already established that the LLM ranked list responds to item names and to candidate order.

### 3. Estimand audit

Two defects.

1. Both arms overwrite the target item title. So the target item no longer exists after treatment. "Target-item rank displacement" is undefined unless you redefine the outcome on the list slot. State the slot definition or the estimand does not exist.
2. The exact test for the list-level sharp null is correct. The list is the correct randomization unit. But a randomization confidence interval for the **average** contrast does not follow from that test. Test inversion delivers an interval only under a constant-effect model. For the average contrast, use the Neyman variance estimator and accept conservative coverage. The prompt has not fixed this yet.

### 4. Most likely fatal assumption

The match on Wikipedia page views controls marginal familiarity. It does not control the association between the substituted title and the specific history items. That association is exactly what a correct recommender must use. So a positive contrast is equally consistent with correct topical reasoning. The rename to "catalogue-specific title advantage" hides the confounder. It does not remove it.

A second problem kills the real-data run. MovieLens 1M holds about 3,883 titles released up to the year 2000, and it already contains the popular films of that era. A disjoint catalogue matched on item type, genre, era, and familiarity must draw from the unpopular remainder of the same era. Era match and familiarity match therefore fight disjointness. The matched design is close to infeasible on this dataset.

**Strongest falsification.** Compute, for each Arm B title, the co-occurrence rate with the user history items in an external corpus. Regress the arm contrast on that rate. If the contrast disappears once you condition on it, the effect is topical relatedness, not catalogue advantage.

### 5. Smallest defensible experiment

2,000 users, 20 candidates, 500 list-level randomizations, one 7B open model, log-probability scoring. About 6 GPU-hours on one card. The synthetic-catalogue LoRA power check adds about 4 GPU-hours.

# F2 — FDR-controlled evidence filter for preference profiles

### 1. Closest prior work

- ContextCite: Attributing Model Generation to Context (NeurIPS 2024) — https://arxiv.org/abs/2409.00729
- GISTBench: Evaluating LLM User Understanding via Evidence-Based Interest Verification — https://arxiv.org/abs/2603.29112
- The Personalization Mirage: How LLMs Fabricate User Profiles — https://arxiv.org/abs/2608.04570
- Transparent and Scrutable Recommendations Using Natural Language User Profiles (ACL 2024) — https://aclanthology.org/2024.acl-long.753/
- The hardness of conditional independence testing and the generalised covariance measure (Shah and Peters, 2020) — https://arxiv.org/abs/1804.07203

### 2. Is the contribution new?

No. ContextCite already ablates context spans and reads the change in the log probability of a fixed generated statement. F2 swaps the ablation for a matched replacement and adds Benjamini-Yekutieli. That is a routine combination of two known tools.

### 3. Estimand audit — this is where F2 fails

The permutation test is not valid. The reason is structural, not statistical noise.

1. The support-like spans are selected because they score above a semantic threshold against the claim text.
2. The control spans come from the complement of that selection. They are low-similarity by construction.
3. The statistic is the teacher-forced log probability of the claim text.
4. Any language model raises the log probability of a target text when the context is semantically near it. This holds even when the model never used those spans to form the claim.

So the null distribution is shifted for every claim. The p-values are anti-conservative. Super-uniformity fails. Benjamini-Yekutieli then controls nothing.

This is the Shah and Peters result. A conditional independence test needs the conditional distribution of the replaced variable. A match on user, category, and sentiment does not supply that distribution, because it does not match semantic distance to the claim, and semantic distance is the driver.

A second, separate defect is arithmetic. With 300 resamples the smallest p-value is 1/301 = 0.0033. Benjamini-Yekutieli at q = 0.10 over m = 8,000 claims uses the threshold q·k/(m·H_m) with H_m ≈ 9.56. To retain 10% of claims you need a p-value below 0.00105. That value is below the resample floor. So 300 resamples cannot produce a filter that removes most claims. You need about 1,000 resamples as a hard floor, and 3,000 for margin. That is a tenfold rise in compute.

### 4. Most likely fatal assumption

The stated exchangeability assumption. The prompt marks it as conditional and therefore honest. It is still false by construction, so the theorem is empty.

**Strongest falsification.** The prompt already names it, and I predict it fails. Generate claims from user A. Test them against user B's history. No claim can depend on any of B's spans. If the retained fraction exceeds the target FDR, the guarantee is broken. Run this before anything else. It costs one afternoon.

### 5. Smallest defensible experiment

1,000 users, 8 claims each, 1,000 resamples, one 7B model, teacher-forced scoring only. About 10 GPU-hours. Run the claim-user shuffle first, at 200 users, for about 2 GPU-hours.

# F3 — Stratified audit certificates for DCG

### 1. Closest prior work

- Minimal Test Collections for Retrieval Evaluation (Carterette, Allan, Sitaraman, SIGIR 2006) — https://people.cs.umass.edu/~ramesh/Site/PUBLICATIONS_files/CAS06.pdf
- A Family of Rank Similarity Measures based on Maximized Effectiveness Difference — https://arxiv.org/abs/1408.3587
- Bootstrapped nDCG Estimation in the Presence of Unjudged Documents — https://downloads.webis.de/publications/papers/froebe_2023a.pdf
- PRECISE: Reducing the Bias of LLM Evaluations Using Prediction-Powered Ranking Estimation (AAAI 2026) — https://ojs.aaai.org/index.php/AAAI/article/view/41427
- Demystifying Prediction Powered Inference — https://arxiv.org/abs/2601.20819
- On (Normalised) Discounted Cumulative Gain as an Off-Policy Evaluation Metric — https://arxiv.org/abs/2307.15053

### 2. Is the contribution new?

Partly. Carterette 2006 already writes a metric difference as a function of unknown labels and bounds it. Maximized Effectiveness Difference already maximizes a metric gap over an admissible label set. The residual idea from rank-biased precision already gives exact metric intervals under unknown labels.

The one new piece is the uncertainty set. F3 replaces "labels unknown" with "at most `b_s` errors per stratum", and it builds `b_s` from a stratified audit. That glue is real but small.

### 3. Estimand audit — the mathematics is right and the result is empty

The mathematics holds. DCG@10 is linear in the binary labels. The average difference between two systems is linear in the pooled label vector. Under a cardinality budget on flips, the greedy choice of the largest signed changes is exactly optimal, and the endpoints are sharp. The hypergeometric upper confidence bound is exact under a sample without replacement. Bonferroni across strata gives simultaneous coverage. I confirm all of it.

The problem is the size of the interval. Run the arithmetic on KuaiRec.

- KuaiRec small matrix: 1,411 users, 3,327 items.
- Two top-10 lists give about 15 pooled pairs per user, so about 21,000 pooled pairs.
- DCG discount weights run from 1.000 at rank 1 to 0.289 at rank 10. The largest coefficients are near 1.0.
- Take an adversarial coefficient of 0.6 per flip.

Half-width ≈ b × 0.6 / 1,411.

A realistic DCG@10 gap between two recommenders is 0.05 to 0.30. To certify a 0.30 gap you need b < 706 errors out of 21,000, which is a 3.4% judge error rate. To certify a 0.05 gap you need b < 118, which is 0.56%.

Published LLM judges do not reach 96% to 99% per-label agreement. At a realistic 15% error rate, b ≈ 3,150 and the half-width is about 1.34. That is 4 to 27 times the true gap. The interval always contains zero. The certification rate is zero.

No audit size repairs this. The audit tightens `b_s` toward the true error count. It cannot push the true error count below 1%.

The two escape routes both close. If you weaken the adversary to random placement inside the budget, you get a sum over a sample without replacement, and the correct estimator for that is prediction-powered inference. PRECISE and PPI already do it, without the extra machinery, and they give a much narrower interval. If you keep the worst case, the interval stays empty.

### 4. Most likely fatal assumption

Not an assumption. An arithmetic fact. The worst-case adversary spends the whole error budget on the highest-weight positions, and a realistic budget swamps the metric gap.

**Strongest falsification.** You do not need a GPU. Take any published DCG@10 gap, any pool size, and any reported judge accuracy. Compute b × mean coefficient / U. Compare it to the gap. Do this on paper today.

### 5. What survives

One statistic survives: the minimum error budget at which the winner flips. On KuaiRec that number will land near 0.1% to 3% of the pool. That is a clean and honest negative result about the robustness of offline recommender comparison. It costs almost no compute. It is not enough to carry a paper, because it is a metrics-only audit, which your own rule kills.

### 6. Scores

| Axis | Score |
|---|---|
| Novelty | 5 |
| Technical depth | 7 |
| Feasibility | 3 |
| Venue fit | 7 |

# Replacements

I killed three, so I owe three. I searched each one myself.

## P1 — Difference in discontinuities at the pretraining cutoff

Replaces F1. It answers the same question with a design that identifies the effect.

**Question.** How much of an LLM recommender's advantage comes from the model having seen the item during pretraining?

**Design.** The item release date is the running variable. The model's data cutoff is the threshold. Estimate the jump in per-item hit rate at the cutoff for the LLM recommender. Estimate the same jump for a collaborative baseline trained on the identical interactions. Take the difference. The baseline has no cutoff, so it differences out any real change in item quality or item popularity at that calendar date.

**Why the design is strong.** The falsification is decisive and rarely available. Run three open models with three different documented cutoffs. Each jump must sit at that model's own cutoff. If all three jumps land on the same date, the effect is calendar time and the design has failed. State this test in advance.

**Novelty check.** Simulated Ignorance Fails (https://arxiv.org/abs/2601.13717) reports a cutoff discontinuity, but only for forecasting, with no discontinuity design and no non-LLM control arm. Dated Data (https://arxiv.org/abs/2403.12958) traces effective cutoffs, not downstream task effects. Filling the Gaps (SIGIR 2026) names the knowledge gap in LLM recommenders but does not identify it causally. I found no difference-in-discontinuities work in recommendation.

**Main risk.** Item counts near the cutoff may be small, so power is thin. Use a wide bandwidth and a donut hole around the threshold. Report the bandwidth sensitivity.

**Compute.** Three open models, about 5,000 users, log-probability scoring. About 15 GPU-hours.

**Scores.** Novelty 6, depth 7, feasibility 6, venue fit 8.

## P2 — Exact history-swap test and a lower bound on the count of personalized users

Replaces F2. It keeps the goal and fixes the exact defect that killed F2.

**Question.** Does the LLM recommender use this user's history, and for how many users?

**Design.** You assign each prompt at random to carry either the user's own history or a donor history matched on length and category mix. You control that assignment. So exchangeability holds by construction, not by assumption. This is the single repair F2 needed.

**Estimand.** Not an average effect. The **count** of users with a non-null effect. Compute an exact per-user permutation p-value. Then apply permutation-based closed testing to get a 1 − α lower confidence bound on the number of true non-nulls. See Meinshausen (2006) and the permutation closed-testing line at https://arxiv.org/abs/1808.05528 and https://arxiv.org/abs/2012.00368.

**Falsification.** Run the same procedure on a fitted SASRec exposed through the same interface. The count must be high. Run it on a popularity-only ranker. The count must be near zero.

**Novelty check.** History shuffle is a known ablation, so the ablation is not the contribution. I found no work that converts it into an exact test with a confidence bound on the number of personalized users. A count with a guarantee is a stronger object than a mean shift, and recommendation research almost never reports one.

**Compute.** 2,000 users, 1,000 permutations, one 1.5B to 7B model, scored by log probability. Share donor histories across users to cut the forward passes. About 12 GPU-hours.

**Scores.** Novelty 6, depth 7, feasibility 7, venue fit 8.

## P3 — A certified count of memorized users in a fine-tuned LLM recommender

Replaces F3. It leaves the evaluation-reliability space, because PPI and PRECISE have closed that space.

**Question.** How many training users has the fine-tuned recommender memorized?

**Design.** Split users at random into train and holdout before the fine-tune. Fine-tune Qwen-1.5B with LoRA on the train sequences. For each train user, compute a membership statistic. Calibrate it against the holdout users. Because the split was random, the holdout statistics are exchangeable with the train statistics under the null, so the conformal p-values are exactly valid. Then apply closed testing to report a 1 − α lower bound on the number of memorized users.

**Why this matters.** The membership inference field reports AUC. A privacy audit needs a count with a guarantee. This idea answers the standing criticism of AUC-only reporting.

**Novelty check.** Membership Inference Attacks on LLM-based Recommender Systems (https://arxiv.org/abs/2508.18665) and the distillation variant (https://arxiv.org/abs/2511.14763) both attack, and both report rates. Self-prompt calibration (https://arxiv.org/abs/2311.06062) improves the statistic. None reports a finite-sample lower bound on the count. The validity argument here is airtight because you own the split.

**Main risk.** Weak signal. If the LoRA fine-tune memorizes little, the bound reads zero. That is still a valid result, and you should say so in advance. Raise the epoch count to create a positive control.

**Compute.** One LoRA fine-tune plus two scoring passes over about 6,000 users. About 8 GPU-hours.

**Scores.** Novelty 7, depth 7, feasibility 8, venue fit 7.
